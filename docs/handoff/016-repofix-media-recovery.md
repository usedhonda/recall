# Handoff: Retained media recovery

- Goal / why: make retained media retryable after process/container replacement and prevent non-network preflight failures from spinning the queue.
- Scope: `MediaUploadManager` startup reconciliation, preflight failures, one existing SwiftData test suite, pipeline documentation.
- Explicitly out: UI, stream toggles, retention policy, Hub receipts, deletion authority, retry caps, device installation/deployment.
- Status: review; native build and tests require an iOS-capable environment.
- Baseline evidence (`cb4d590396b9eb685302f3a46afa01c3c2fa1023`): media uses an ephemeral URLSession, writes `.uploading`, but never resets these rows after process restart. Selection admits only pending/failed rows. Absolute retained media paths are not repaired after a container move although audio already does this. Missing files return before incrementing attempts or recording an attempt time; invalid URLs return without any delay. Empty Hub originals return before the common retry timestamp/delay. Each early return can select the same row again immediately.
- Changes: once per process, before the first drain, restore in-flight rows to pending and re-point missing paths only when a filename-matching replacement exists in the current media directory. Preserve attempts and Hub/legacy receipts. A failed save prevents the drain and is retried on a later start. Missing-file reads use the existing counted/backed-off read-error path. Invalid configuration retains the row and yields for ten seconds without spending its retry budget. Empty Hub originals remain failed/retryable under the existing Hub pacing.
- Validation: `bash scripts/check-contract.sh` passed; source/diff review verified restart selection, guarded path repair and all three formerly unpaced exits. The native regression exercises real SwiftData recovery and persistence, file preservation, unchanged failed/uploaded rows and idempotence, but was not executed here because Swift/Xcode/iOS SDK are unavailable.
- Test accounting: added 1 / removed 0 / consolidated 0; `OptionalDatePredicateTests` changes from 2 to 3 methods, keeping the earlier selection and stale-audio regression boundaries intact. No new test file or testing abstraction.
- Next verification: build and run `OptionalDatePredicateTests`; with synthetic media, confirm restart recovery and that invalid/missing/empty inputs yield without claiming delivery or deleting originals. Native networking and device behavior remain unverified.
- Rollback: revert source/doc/test changes; no schema or persisted-format migration.
- Model/API review: no provider/model/endpoint/payload/dependency changes. Existing ephemeral URLSession transfers are process-owned; this patch repairs their local recovery state.
